# 도서관 홈 v2 기획안 — 토스식 접근 (제안)

상태: 제안 (미구현). v1(필터 수정·검색·이어읽기·`books.json` 분리)이 먼저 반영된 상태를 전제로 한다.
출처: 토스 디자인 원칙을 참고한 해석이며, 토스의 실제 내부 방식이 아니다.

## 1. 문제 정의
동화가 늘수록 "오늘 읽을 책 하나 고르기"가 어려워진다. v1은 필터·검색으로 찾는 수단을 늘렸지만, 홈이 여전히 전체 목록 중심이라 책이 20권 이상이 되면 같은 문제가 다시 생긴다. v2의 목표는 목록을 줄여서 보여주는 것이 아니라, 선택 자체를 쉽게 만드는 것이다.

## 2. 핵심 원칙
1. 한 화면에는 한 가지 목적만 둔다. 홈의 목적은 "오늘 읽을 책 고르기"다.
2. 분류가 아니라 상황으로 묻는다. "과학 탐험"보다 "궁금한 게 많아요"가 부모와 아이가 바로 답하기 쉽다.
3. 쉬운 말과 일정한 형식을 쓴다. 전문 용어(회복탄력성 등)를 일상어로 바꾸고, 분량은 "7분 · 10장면"으로 통일한다.
4. 다음 행동은 하나만 크게 보여준다. 카드마다 작은 링크를 두지 않고, 엄지가 닿는 위치에 큰 버튼을 둔다.
5. 빈 상태에도 다음 행동을 준다. "준비 중"에서 끝내지 않고 비슷한 책을 제안한다.

## 3. 홈 구조 (위에서 아래로)
- 이어 읽기: 마지막으로 연 책 1권을 큰 카드로. 처음 방문이면 "처음 읽기 좋은 책"으로 대체한다.
- 새로 나온 이야기: 최신 1~2권.
- 오늘 어떤 이야기가 필요해요?: 상황 질문 칩(속상해요 / 친구와 놀고 싶어요 / 궁금한 게 많아요 / 7분 안에 읽기). 누르면 해당 책만 보인다.
- 주제별 가로 스크롤 줄: 줄마다 책 3~4권이 보이고 옆으로 넘긴다. 세로 길이는 책 수와 무관하게 일정하다.
- 전체 보기: 지금의 v1 목록(검색·정렬 포함)으로 연결한다.

## 4. 문구 규칙
- 분류명은 상황어로: 마음과 감정 → "속상할 때 읽어요", 친구와 용기 → "친구와 놀고 싶어요".
- 메타 정보는 한 줄, 같은 형식: "7분 · 10장면 · 5~7세".
- 버튼은 동사로: "이어서 읽기", "처음부터 읽기".

## 5. 책 읽기 화면 연계 (v2.1)
현재 "읽음"은 카드 클릭 기준이라 실제로 끝까지 읽었는지 알 수 없다. 읽기 화면에 다음을 넣어야 정확해진다.
- 상단 진행률 바와 현재 장면 번호.
- 마지막 읽은 위치 저장(`localStorage`).
- 끝 장면에서 "다음에 읽을 책" 1권 제안.
- 글자 크기 조절.
- 이 부분은 책 HTML 8개를 모두 건드리므로 별도 작업으로 분리한다.

## 6. 데이터 변경
`books.json`에 항목 추가: `mood`(상황 태그 1~2개), `minutes`(숫자), `age`(권장 연령). 기존 `tags`는 유지하되 홈에서는 `mood`를 우선 쓴다. 태그 값은 책을 새로 올릴 때마다 정해야 하므로 운영 가이드에 기준을 적는다.

## 7. 성공 지표
- 홈 진입부터 책 선택까지 걸리는 시간.
- 재방문 시 "이어 읽기" 클릭 비율.
- 책 끝 장면 도달 비율(5절 반영 후).
혼자 쓰는 정적 사이트라 자동 수집은 없다. 필요하면 가족이 직접 써보는 관찰로 대신하고, 분석 도구 도입은 별도 결정으로 둔다.

## 8. 위험과 열린 질문
- 상황 질문은 책 수가 적을 때(현재 6권) 결과가 1권뿐일 수 있다. 질문당 최소 2권이 확보될 때 노출한다.
- 가로 스크롤 줄은 키보드·스크린리더 접근성 검증이 필요하다.
- 상황 문구는 아이 연령별 톤이 다르다. 문구 확정은 사용자(보호자) 검토가 필요하다.
- 5절은 책 파일 전체 수정이라 범위가 크다. v2와 분리할지 결정이 필요하다.

## 9. 단계
1. v2: 홈 구조 개편(3절), `books.json` 확장(6절). 구현 전 가로 줄 UI 시안 확인.
2. v2.1: 읽기 화면 진행률·위치 저장(5절).
3. v2.2: 지표 관찰과 문구 조정.
