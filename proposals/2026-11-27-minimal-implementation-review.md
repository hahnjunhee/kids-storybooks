# 책장 기능 최소 구현 검토의견 (v3.1 기준)

상태: 검토의견 (미구현). 대상: 통합 기획안 v3.1(`docs/plans/library-ux/plan-v3.md`)의 기능을 큰 개발 없이 구현하는 방법.

## 결론
새 파일·프레임워크·빌드 단계 없이 `index.html` 한 파일의 스크립트와 `books.json`의 필드 한 개로 모두 구현할 수 있다. 예상 변경은 `index.html` 약 40~60줄, `books.json` 책당 한 필드다. v1(`a73bd2b`)이 이미 검색·필터·정렬·최근 열람·`books.json` 분리를 갖고 있어서, 새로 만드는 것은 최초 발행일, 제목순, 셔플, 즐겨찾기, 뒤로 가기 복원 다섯 가지뿐이다.

## 기능별 가장 단순한 방법
1. 최초 발행일: `books.json`에 `"publishedAt":"2026-11-22"` 문자열 한 필드를 추가한다. 화면에는 문자열을 `-`로 쪼개 `2026.11.22`로 표시한다. `Date`로 파싱하지 않는다(시간대 때문에 하루가 밀리는 문제를 피한다). 값이 없으면 날짜 줄을 그리지 않고 정렬에서 맨 뒤로 보낸다.
2. 최신순·제목순: 정렬 기준만 바꾼다. 최신순은 `publishedAt` 내림차순(같은 날짜면 `no` 내림차순), 제목순은 `localeCompare('ko')`.
3. 셔플: 정렬 드롭다운 옆에 버튼을 따로 둔다(드롭다운 항목으로는 "다시 섞기"를 할 수 없다). 버튼을 누르면 임의의 시드 숫자를 `sessionStorage`에 저장하고, 그 시드로 현재 결과 목록을 Fisher–Yates로 섞는다. 배열 전체를 저장하지 않고 시드만 저장하므로 책이 추가되어도 복원이 깨지지 않는다. 정렬 드롭다운을 바꾸면 셔플은 해제한다. 필터·검색을 바꿔도 같은 시드를 쓰므로 결과 집합만 달라지고 셔플은 유지된다.
4. 즐겨찾기: 카드 안에 ♥ 버튼을 둔다. 링크(`<a>`) 안에 버튼을 넣으면 잘못된 구조이므로 카드를 `<div>`로 감싸고 링크와 ♥ 버튼을 형제로 둔다. 저장은 `localStorage`의 id 배열 하나다. 필터 칩에 "♥ 즐겨찾기"를 하나 더한다.
5. 뒤로 가기 복원: 검색어, 필터, 정렬, 셔플 시드, 스크롤 위치를 `sessionStorage`의 객체 하나에 저장하고(입력·클릭 때와 링크 클릭 직전), 페이지 로드 후 목록을 그린 다음 복원한다. 목록을 `fetch`로 그리기 때문에 브라우저 기본 스크롤 복원이 믿을 수 없으므로, 그린 뒤 `scrollTo`를 직접 호출한다.
6. 저장 실패: 모든 `localStorage`/`sessionStorage` 접근은 `try/catch`로 감싸고 실패하면 기본 상태로 동작한다(v1에 이미 있는 방식을 재사용).

## 하지 않는 것
서버, DB, 프레임워크, 번들러, 추가 페이지, 분석 도구, 추천 알고리즘, 상황 질문(mood), 가로 스크롤 줄. 읽기 화면(책 HTML 8개) 수정도 이 작업에서 제외한다.

## 최초 발행일 후보 (확인 필요)
`git log --follow`로 각 파일이 처음 추가된 커밋 날짜를 조사한 값이다. 첫 커밋 날짜가 실제 첫 공개일과 다를 수 있으므로 사용자 확인 후 등록한다.
- 루루야, 나도 같이 놀아도 돼? — 2026-11-21 (`151b311`)
- 루아와 해달의 신비로운 바다숲 — 2026-11-22 (`12a018a`)
- 반짝반짝 영흥도 바다 여행 — 2026-11-22 (`148db6c`)
- 꽃을 피우다, 정원사 — 2026-11-22 (`aa90f04`)
- 루아와 공룡이 남긴 비밀 — 2026-11-25 (`dab313d`)
- 찌릿찌릿! 전기뱀장어의 비밀 — 2026-11-26 (`7d4c093`)
세 권이 같은 날(11-22)이므로 최신순 보조 기준으로 `no`가 필요하다.

## 구현 순서
1. `books.json`에 `publishedAt` 등록(위 날짜 확인 후). 이 단계 전에 최신순을 날짜 기준으로 바꾸면 날짜 없는 책이 뒤로 밀려 오히려 틀리므로 반드시 먼저 한다.
2. 정렬(최신순·제목순) + 날짜 표시.
3. 셔플 버튼 + 시드 저장.
4. ♥ 즐겨찾기 + 필터 칩.
5. 상태 저장·복원.
각 단계는 독립적이라 한 커밋씩 나눌 수 있고, 4·5는 필요가 확인될 때까지 미뤄도 된다.

## 검증 (가볍게)
- 임시 `books.json`을 50권으로 부풀려서 검색·필터·정렬·셔플이 정상인지 로컬에서 확인한다(저장소에 포함하지 않음).
- 셔플 전후로 결과 개수가 같고 중복·누락이 없는지.
- 책을 열었다가 뒤로 왔을 때 검색어·필터·셔플 순서·스크롤이 유지되는지.
- 320~480px 폭에서 잘림 없음, 터치 영역 44px 이상, 키보드 포커스 표시.
- `localStorage`를 막은 상태에서 목록이 정상 표시되는지.

## 위험과 한계
- 날짜 후보는 git 이력 기반이라 실제 공개일과 다를 수 있다.
- 즐겨찾기·읽음은 브라우저별 저장이라 기기 간 동기화되지 않는다(서버 없음).
- 6권에서는 셔플의 체감이 작다. 구현 비용이 낮아 함께 넣되 우선순위는 발행일 정렬이 위다.
- 실제 라이브 사이트와 모바일 기기 검증은 아직 하지 않았다.
