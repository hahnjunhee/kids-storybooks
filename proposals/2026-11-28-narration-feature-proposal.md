# 그림책 낭독(듣기) 기능 기획안

상태: 기획안 초안 (미구현, 미승인). 대상: 도서관의 모든 그림책 상단바. 근거 시험: `video-test/TTS_RESEARCH.md`.

## 결론
각 그림책 상단바에 "듣기" 버튼을 넣는다. 음성은 MeloTTS(한국어)로 **미리 합성한 MP3**를 장면별 파일로 제공하고, 책 HTML은 `<audio>` 하나로 재생한다. MeloTTS는 Python·PyTorch 모델이라 브라우저에서 실행할 수 없고, 읽는 사람의 기기에서는 파일만 재생한다. 읽는 동안 현재 문단을 강조하고 장면이 끝나면 다음 장면으로 넘어간다. 책 HTML의 증가량은 약 3KB 이하(스크립트와 매니페스트)로 500KB 목표를 해치지 않고, 오디오는 HTML 밖에 둔다.

## 시험에서 확인된 사실 (2026-11-28, 전기뱀장어 1~3장)
- MeloTTS 한국어 합성은 이 클라우드 환경의 CPU에서 동작한다. 합성 속도는 실시간의 약 0.3배.
- 낭독 속도는 문단당 약 0.15초/자. 장면당 낭독 17~21초, 책 한 권(12장면, 약 2,100자)은 약 5분으로 추정한다.
- 합성 결과에 문장 중간 약 1.1초, 끝 0.8~1.4초의 무음이 있어 후처리가 필요하다.
- 화자는 한 명뿐이다(`KR`). 음질은 아직 사람이 들어서 평가하지 않았다.
- 설치가 무겁다(PyTorch와 CUDA 라이브러리 약 5GB, Python 3.10 필요). 그래서 합성은 저장소 밖(클라우드 세션)에서 한 번만 하고 결과 MP3만 저장소에 올린다. GitHub Actions에서 매번 합성하지 않는다.

## 사용자 경험
- 상단바에 `🔊 듣기` 버튼 하나. 누르면 현재 화면에 보이는 장면부터 읽기 시작한다(자동재생 금지, 반드시 누를 때만).
- 재생 중에는 `⏸ 멈춤`, 속도 `느리게 / 보통 / 빠르게`(0.9 / 1.0 / 1.15), 이전·다음 장면 이동. 4~6세 대상이라 기본은 보통으로 두되 청취 평가 후 조정한다.
- 세로 스크롤 모드: 읽는 장면으로 부드럽게 이동하고, 읽는 문단에 배경색을 입힌다. 사용자가 직접 스크롤하면 자동 따라가기만 멈추고 음성은 계속 나온다.
- 페이지 넘기기 모드: 장면이 끝나면 다음 장으로 자동 넘김. 모드를 바꿔도 재생 위치는 유지한다.
- 마지막 장면이 끝나면 자동으로 멈춘다. 화면이 꺼져도 잠금화면 컨트롤(Media Session)로 재생·멈춤이 가능하다(안드로이드 크롬).
- 음성이 "AI 음성"임을 버튼 근처 작은 글씨로 표시한다.
- 오프라인이거나 음성 파일을 못 받으면 버튼을 비활성으로 두고 "인터넷 연결이 필요해요"를 보여 준다. 글 읽기는 기존처럼 오프라인에서 된다.
- 인쇄 시에는 버튼을 숨긴다.

## 기술 설계
**오디오 보관.** `audio/<book-id>/sNN.mp3`(장면당 1파일, 모노, 약 64kbps)를 저장소에 둔다. 책 HTML에 Base64로 내장하지 않는다(내장하면 약 4/3로 불어나 500KB 목표를 크게 넘는다). 권당 약 2~3MB, 8권 약 15~20MB로 추정한다(미측정).

**매니페스트.** 책 HTML에 `<script type="application/json" id="narration">` 한 덩어리를 넣는다. 내용은 장면별 `{선택자, 파일, 길이, 문단별 시작초}`이다. 문단 시작초는 합성 때 측정한 값을 쓰므로 단어 단위 타임스탬프는 필요 없다.

**책마다 구조가 달라서 어댑터가 필요하다.** 현재 `books.json`의 8권을 보면 `.spread` 섹션 구조(루루, 해달, 영흥도, 전기뱀장어), 클래스 없는 `<section>` 구조(`craft-museum`, `blood-friends`, `lua-pink-bicycle`), 섹션이 2개뿐인 공룡 책(`dinosaur`)으로 나뉜다. 상단 `header`도 없는 책이 둘(`blood-friends`, `lua-pink-bicycle`) 있고, 루루는 이미지가 Base64가 아니라 `assets/`의 별도 파일이다. 그래서 스크립트는 구조를 가정하지 않고 매니페스트의 `장면 선택자`와 `문단 선택자`로 대상을 찾는다. 책별 선택자는 구현 1단계에서 조사해서 확정한다.

**재생.** `<audio>` 요소 하나를 장면마다 `src`만 바꿔 쓴다. `preload="none"`이고, 재생 중 다음 장면 파일만 미리 요청한다. 문단 강조는 `timeupdate`에서 문단 시작초와 비교한다.

**삽입 방식.** 스크립트 약 60~80줄을 각 책 HTML에 인라인으로 넣는다(독립형 단일 HTML 원칙 유지, 외부 라이브러리 없음). 공통 열람 템플릿(`templates/storybook.html`)에도 같은 블록을 추가한다.

**생성 파이프라인.** `tools/narration/`에 스크립트를 둔다. 책 HTML에서 문단 추출 → MeloTTS 합성 → 앞뒤 무음 다듬기 → 장면별 MP3 → 매니페스트 생성의 순서다. 합성 엔진은 MP3와 매니페스트만 만들어 내므로, 청취 평가 결과에 따라 다른 엔진(예: Google Cloud TTS)으로 바꿔도 책 쪽 코드는 그대로다.

**발음 교정.** 숫자, 외래어, 의성어(`찌릿찌릿` 등)와 따옴표 낭독이 어색할 수 있다. 책별 발음 치환표를 두고 사람이 모든 장면을 들어서 확인한다. 화면에 보이는 글은 건드리지 않고 낭독용 텍스트만 치환한다.

## 콘텐츠·운영 원칙
- 원작 보존: 낭독 텍스트는 화면 본문과 같아야 한다. 발음 치환 외에는 고치지 않는다.
- 낭독 범위 기본안: 책 제목, 장 소제목, 본문. 제외: 쪽 번호, 제작 메모, 삽화 설명. 발견 노트와 학습 카드(C형)는 결정 필요(아래).
- 아동 정보: 실제 아동의 이름·목소리를 쓰지 않는다. 별칭은 기존 원칙(기본 `루아`)을 따른다. 사람 목소리 복제는 하지 않는다.
- 라이선스: MeloTTS 한국어 모델은 모델 카드에 MIT로 표기돼 있다. 공개 배포 전에 학습 데이터 출처까지 포함해 다시 확인한다(시험에서는 확인하지 못했다).
- 검증 표기: 자동화하지 않은 청취 검수와 실기기 재생은 완료했다고 표시하지 않는다(가이드라인의 검증 원칙).

## 범위
포함: 모든 책의 상단 듣기 버튼, 속도 3단계, 문단 강조와 장면 자동 이동, 잠금화면 컨트롤, 도서관 홈 카드의 🔊 배지(`books.json`에 `narration` 필드).
제외: 영상(Hyperframes) 파생물(별도 트랙), 다중 화자·감정 표현, 사용자 녹음, 서비스워커 오프라인 캐시, 분석 도구.

## 대안 비교
- **A. 사전 합성 MP3 (권장).** 기기와 무관하게 같은 음성, 문단 강조 정확. 저장소 용량과 합성·검수 작업이 든다.
- **B. 브라우저 내장 음성(`speechSynthesis`).** 저장 용량 0, 오프라인 가능. 하지만 기기마다 음성이 다르고 한국어 음성이 없는 기기도 있으며, 문단 강조 정확도가 낮다. 청취 평가가 나쁠 때의 폴백 후보로만 둔다.
- **C. 클라우드 TTS 사전 합성(Google Cloud TTS 등).** 음질이 더 나을 수 있으나 키와 결제 계정이 필요하고 아직 시험하지 않았다. A와 구조가 같아서 엔진만 바꾸면 된다.

## 단계
0. 결정: 청취 평가, 아래 결정 요청 승인. (이 단계가 끝나기 전에는 구현하지 않는다.)
1. 시범 한 권(전기뱀장어): 12장면 합성·검수, 스크립트 삽입, 안드로이드 크롬 실기 재생. 책별 선택자 조사.
2. 변환 스크립트(`tools/narration/`)와 공통 템플릿 정리, 가이드라인에 "낭독" 절 추가(v3.1.3 후보).
3. 나머지 책 적용, 홈 카드 배지. 책마다 합성·청취 검수를 거친 뒤 한 권씩 커밋한다.

검증 항목: 장면별 재생 시작·종료, 문단 강조 동기, 세로↔페이지 전환 시 재생 유지, 사용자 스크롤 시 자동 따라가기 중지, 인쇄 시 버튼 숨김, 오프라인 시 안내, 320~480px 폭에서 잘림 없음, 터치 영역 44px 이상, 키보드 조작(Space), `localStorage` 차단 시 정상 동작, 책 HTML 증가량 3KB 이하.

## 위험과 한계
- 음질이 기대에 못 미칠 수 있다(청취 평가 전). 이 경우 엔진 교체 또는 보류.
- 저장소 용량이 바이너리로 늘어난다. 재합성할 때마다 이력이 커지므로 변경된 장면만 다시 합성한다.
- 합성 결과는 모델·버전·설치 환경에 따라 달라질 수 있다. MP3만 저장소의 기준 자료로 삼고, 합성 환경(버전)은 `tools/narration/README`에 기록한다.
- 책 8권의 구조가 달라서 어댑터 확정 전까지 일정이 불확실하다.
- 오디오는 별도 파일이라 책 HTML만 따로 보관하면 음성이 빠진다.

## 결정 요청
1. MeloTTS 샘플(`melo-sample-3scenes.mp3`)을 듣고 음질이 충분한지 판단.
2. 기존 책 전체에 소급 적용할지. 가이드라인은 "기존 작품 소급 없음"을 원칙으로 두고 있어서 이 기능은 예외 승인이 필요하다.
3. 오디오 파일을 저장소에 직접 커밋해도 되는지(권당 2~3MB).
4. 발견 노트·학습 카드·표지 소개 문구를 낭독할지.
5. 가이드라인 반영 방식: 신규 "낭독" 절(v3.1.3)로 추가할지.
