# 생활동화 제작 개선 기획안 — v3.0 제안

- 작성일: 2026-11-25
- 상태: 검토용 기획안 (미승인·미시행)
- 기존 v2.3 가이드 및 완성 동화는 변경하지 않는다.
- 아래 수치와 구조는 제안이며 실제 운영 규칙이 아니다.

## 1. 배경과 목표
최근 공룡동화 및 영흥도 동화 제작에서 본문과 삽화 불일치, 같은 장면 반복 생성, 실명 노출, 콜라주 출력, 깨진 이미지, C형 텍스트 누락, 수정 장기화 문제가 나타났다. 목표는 프롬프트 개선뿐 아니라 상태관리와 품질통제를 통해 불필요한 이미지 생성 자체를 줄이는 것이다. 기존 제작 이력의 정량 수치는 별도 원장으로 검증하기 전 확정하지 않는다.

## 2. 제작 프로세스
1. 독자 연령, 교육 목표, 소재 확정
2. 본문 및 발견 노트 작성·사실 검증
3. 전체 스토리보드와 장면 명세 작성
4. 장면 중복 사전 검토, 캐릭터 시트·골든 샘플 확정
5. 미완료 이미지 순차 생성 및 개별 검수
6. 승인 이미지로 HTML 조립
7. 파일·시각·모바일 품질 검증
8. GitHub 반영 및 배포

## 3. 반복 생성 방지 핵심 규칙
### 3.1 고유 ID와 장면 명세
각 이미지에 DIN-05-A 같은 고유 ID를 부여한다. 명세에는 유형, 연결 본문, 핵심 행동, 필수/금지 요소, 구도, 참고 이미지, 비율, 텍스트, 검수 기준을 포함한다. 예: 공룡 앞다리 관찰 장면에는 앞다리와 박물관 배경을 요구하고 이전 오류인 발자국·실명·콜라주를 금지한다.
### 3.2 영속적 관리대장
image-manifest.json에 ID, 상태, 명세 버전, 생성 횟수, 파일 경로, 해시, 검수 결과, 오류 사유를 기록한다. 상태는 pending → generating → review → approved 또는 blocked로 관리한다. 실행 전 관리대장과 실제 파일을 대조하고 승인된 ID는 건너뛴다. 중단 후 재개 시 generating 상태의 산출물 존재 여부부터 확인한다. 중복 실행 방지를 위해 작업 잠금과 시도별 식별자를 둔다.
### 3.3 시각적 중복 사전 제거
인물 위치, 카메라 거리, 행동, 배경, 주요 피사체를 장면 간 비교한다. 캐릭터와 화풍은 유지하되 중거리 이야기, 특징 확대, 넓은 공간 등 구도를 다양화한다.
### 3.4 생성 단위와 즉시 검수
한 요청당 독립 이미지 한 장을 기본으로 한다. 명세 확인 → 생성 → 파일 저장 → 시각 검수 → 승인 잠금 → 다음 ID 순서로 진행한다. 사용자의 매 장 승인 없이 자체 검수를 수행하되 필수 기준을 완화하지 않는다.
### 3.5 오류 등급과 재시도 예산
| 등급 | 사례 | 처리 |
|---|---|---|
| P0 | 실명, 잘못된 생물, 다른 장면 | 필수 수정 |
| P1 | 본문 불일치, 필수 요소 누락, 콜라주 | 수정 또는 재생성 |
| P2 | 경미한 색상·구도 차이 | 원칙적으로 유지 |
| P3 | 미적 취향 | 재생성하지 않음 |

최초 1회 + 수정 최대 2회를 기본 예산으로 제안한다. 3회 실패 시 blocked로 전환하고 원인을 분석한다. 필수 오류가 남으면 배포하지 않는다. 실패 원인을 수정 프롬프트에 반영하고 동일 요청을 맹목적으로 반복하지 않는다.
### 3.6 최소 수정 우선
핵심 교육 내용과 사실을 보존하는 범위에서 불필요한 행동·색상 묘사는 본문을 조정할 수 있다. 파일 경로 오류는 파일 수정으로, 텍스트 오류는 텍스트 합성으로, 국소 오류는 부분 편집으로 해결한다. 잘못된 과학적 사실을 삽화에 맞춰 변경하지 않는다.
### 3.7 승인 잠금 및 중복 탐지
승인 이미지의 SHA-256을 기록하고 명시적인 변경 사유 없이 재생성·교체하지 않는다. SHA-256으로 동일 파일, pHash로 시각적 유사 후보를 탐지한다. pHash는 자동 삭제가 아닌 추가 검수 신호로 사용한다. 본문 수정 시 영향을 받는 ID만 재검토한다.

## 4. 이미지 스타일 및 텍스트
기존 v2.3의 A/B/C-1/C-2 분류와 세부 규격을 유지한다. A형은 인물·이야기, B형은 풍경·상황, C형은 관찰·설명 또는 비교·탐구에 초점을 둔다. 정확한 유형 정의는 시행 전 원본과 대조한다.
C형의 필수 한글 텍스트 규칙은 유지한다. 그림과 텍스트를 분리 제작한 후 정확한 한글을 최종 독립 이미지에 합성하는 방식을 제안한다. HTML 텍스트만으로 대체하지 않는다. 제목·설명·가독성·오탈자를 검수한다.
캐릭터 시트와 승인 골든 샘플을 매번 기준으로 사용하며 직전 삽화는 연속성 보조 자료로만 사용한다. 얼굴·헤어·신체 비율·화풍은 고정하고 자세·표정·시점은 변화시킨다. 실제 도구의 참조 이미지 전달 가능성은 구현 전에 확인한다.

## 5. 제안 데이터 구조
```json
{
  "id": "DIN-05-A",
  "type": "A",
  "status": "approved",
  "attempts": 1,
  "spec_version": 1,
  "file": "images/din-05-a.webp",
  "locked": true,
  "sha256": "<actual hash>",
  "checks": {
    "story_match": true,
    "character_consistency": true,
    "aspect_ratio": true,
    "privacy": true,
    "single_image": true
  }
}
```
향후 도입 후보: storyboard.json, image-manifest.json, review-report.md, references/, validate-images.py, detect-duplicates.py, validate-storybook.py. 실제 경로는 기존 저장소 구조에 맞춰 결정한다.

## 6. 배포 전 품질 게이트
자동 검사: 파일 존재·디코딩·HTML 경로·규격·동일 파일·승인 해시·필수 상태.
보조 검사: pHash 유사 후보, 이미지 내 실명 탐지, C형 텍스트 데이터.
시각 검사: 콜라주 여부, 본문 일치, 캐릭터 일관성, 과학적 정확성, 한글 가독성, 모바일 렌더링.
자동 검사와 시각 검수를 구분하고 필수 검증 실패 시 배포를 차단한다. GitHub Actions 연계는 후속 구현으로 검토한다.

## 7. KPI (잠정 목표)
| 지표 | 목표 |
|---|---:|
| 최초 생성 승인율 | 80% 이상 |
| 최종 이미지당 평균 생성 횟수 | 1.3회 이하 |
| 승인 이미지 불필요 재생성 | 0건 |
| 실명 노출·깨진 이미지·의도하지 않은 콜라주 | 각각 0건 |
| 최종 필수 본문 불일치 | 0건 |

모든 생성 시도를 분모에 포함하고 실패·중단도 기록한다. 신규 동화 3~5편으로 실측 후 목표를 조정한다. 예시로 활용률 31.25%와 80%를 가정하면 최종 13장에 필요한 생성 횟수는 약 42회와 17회로 추정되나, 실제 절감률을 보장하지 않는다.

## 8. 후속 문서 및 우선순위
- 생활동화 제작 통합 가이드 v3.0: 전체 절차 및 완료 기준
- 이미지 스타일 가이드 v2.3: 기존 문서 유지
- 이미지 생성 운영 프로토콜 v1.0: ID, 상태, 재시도, 잠금
- 품질 검증 체크리스트 v1.0: 자동·시각 검수 및 배포
- P0: 관리대장, 장면 명세, 승인 잠금, 재시도 제한
- P1: C형 텍스트 합성, 파일 검증, 골든 샘플 참조
- P2: pHash, KPI 기록

## 9. 적용 범위 및 승인 조건
이 문서는 기획안만 보존한다. 기존 가이드 수정, 코드 구현, 이미지 생성, 기존 동화 변경, 배포 설정 변경은 수행하지 않는다. 사용자 승인 후 기존 가이드 원문 및 도구 제약을 확인하고 신규 동화부터 시범 적용한다.
