# 수정 기획안: 장면별 이미지 생성 절차 보강

> 상태: **제안(미반영)** · 작성일: 2026-11-22 · 대상: `STORYBOOK_GUIDELINES.md` v2.0, `ILLUSTRATION_STYLE_GUIDE_V2.3.md`
> 이 문서는 기존 가이드를 수정하지 않는다. 승인 시 아래 "변경안"대로 별도 PR로 반영한다.

## 1. 문제

여러 장면의 삽화를 만들 때 장면이 하나의 이미지에 합쳐지는 콜라주가 반복된다.

## 2. 현행 가이드 점검 결과

| 이미 있는 규칙 | 위치 |
| --- | --- |
| 장면마다 독립 원본 생성, 콜라주를 잘라 쓰기 금지 | STORYBOOK §2, IMAGE §8-3 |
| 부정 프롬프트 `no collage` | IMAGE §7 [7 NEGATIVE] |
| 골든 샘플·캐릭터 시트, 콘택트 시트 검수 | STORYBOOK §2, IMAGE §8 |
| 이미지 수·누락·중복 해시 자동 점검 후보 | STORYBOOK §4 |
| 필수 실패는 평균 점수로 상쇄하지 않음 | STORYBOOK §4 |

**부족한 것:** 금지 규칙은 있으나 이를 지키게 하는 **절차**가 없다. 구체적으로 다음이 비어 있다.

1. 한 번의 생성 요청에 몇 장면을 넣는가 (호출 단위)
2. 장면 목록을 언제 확정·잠금하는가
3. 검수 실패 시 재시도 한도와 중단 기준
4. 원인 구분 (모델 출력 자체가 콜라주인가, 저장·조립 단계에서 합쳐졌는가)
5. 이미지 수와 장면 수 불일치를 게시 차단 사유로 명시

프롬프트 문구 강화(`no collage` 추가)만으로는 해결되지 않는다는 점이 전제다.

## 3. 변경안

### 3-1. `STORYBOOK_GUIDELINES.md`

**§2 삽화·캐릭터 일관성** — 기존 bullet 교체

```diff
-- **장면마다 독립 원본을 생성한다.** 여러 장면을 한 장으로 생성하고 잘라 사용하는 방식은 금지한다.
+- **장면마다 독립 원본을 생성한다.** 한 번의 생성 요청에는 장면 1개만 넣고, 서로 다른 장면을 하나의 프롬프트에 나열하지 않는다. 여러 장면을 한 장으로 생성하고 잘라 사용하는 방식은 금지한다. 매 요청에 스타일 접두문과 기준 이미지를 함께 사용한다.
```

**§4 품질 게이트** — 자동 점검 후보에 추가

```diff
+- 이미지 수 = 장면 수 일치, 장면 순서·파일 매핑 일치
```

필수 실패 목록에 추가(문구)

```diff
+필수 실패에 **장면 수와 이미지 수 불일치, 중복 이미지, 콜라주·분할 화면 잔존**을 포함한다.
```

**§5 제작 승인** — 1·2단계 보강

```diff
-1. **기획 확정:** 원고 방향·장면·스타일·별칭 결정
-2. **제작·검증:** 독립 삽화, HTML, 이미지별 최적화, 자동 및 육안 점검
+1. **기획 확정:** 원고 방향·**장면 목록(번호·유형·한 줄 요약)**·스타일·별칭 결정. 확정 후 장면 목록은 잠그며, 변경 시 영향받는 장면만 재생성한다. 원작이 있으면 원작을 고치지 않고 사건 단위로 장면을 나눈다.
+2. **제작·검증:** **장면별로 생성 → 검수 → 통과 → 다음 장면** 순서로 진행한 뒤 HTML, 이미지별 최적화, 자동 및 육안 점검
```

**변경 이력:** `v2.1 (날짜): 장면 목록 잠금, 장면 단위 생성·검수 순서, 이미지·장면 수 일치 게이트 추가.`

### 3-2. `ILLUSTRATION_STYLE_GUIDE_V2.3.md`

**§8 일관성·생성·수정** — 항목 추가

```diff
+7. **호출 단위:** 한 번의 생성 요청에 장면 1개만 포함한다. 가능하면 장면마다 새 요청(또는 새 대화)으로 보내고, 스타일 접두문과 기준 이미지를 매번 함께 사용한다. 콜라주·분할 화면·만화 칸은 명시적으로 요청한 경우에만 허용한다.
+8. **장면별 검수:** 생성 직후 확인한다. 공통은 단일 장면 여부와 인물 일관성, A/B는 문자 없음, C는 한국어 텍스트와 사실 검수다. 통과한 장면만 독립 파일로 저장한다.
+9. **재시도:** 검수 실패 시 해당 장면만 최대 2회 재생성한다. 계속 실패하면 중단하고 원인(프롬프트·참조 이미지·장면 설정)을 비공개 기록에 남긴다.
+10. **원인 구분:** 콜라주가 보이면 먼저 생성 원본을 확인한다. 원본이 정상인데 결과물에서 합쳐졌다면 프롬프트가 아니라 저장·변환·HTML 조립 단계(파일 매핑, 순서)를 점검한다.
```

**§12 최종 검수 체크리스트** — 추가

```diff
+- [ ] 장면 1개당 생성 요청 1회로 만들었고, 이미지 수와 장면 수가 일치하는가?
+- [ ] 콜라주·분할 화면이 남아 있지 않은가? (콘택트 시트 기준)
```

**변경 이력:** `v2.3.1 (날짜): 호출 단위, 재시도 한도, 원인 구분 절차 추가.`

## 4. 하지 않는 것

- 새 `PRODUCTION_FLOW.md`는 만들지 않는다. 기존 3단계 흐름과 중복된다.
- 공개 저장소에 올리지 않는다: 캐릭터 고정문, 기준 이미지, 고해상도 원본, 장면별 프롬프트·재시도 기록. 공개 규칙(IMAGE §2, STORYBOOK §3)을 그대로 따라 비공개로 보관한다.
- 생성 도구(ChatGPT 앱, API 등)를 특정하지 않는다.
- 이번 PR에서 조립 스크립트를 만들지 않는다. 저장소에 생성·조립 코드가 없고 HTML 제작 방식이 세션별이므로 별도 과제로 둔다.

## 5. 반영 절차

1. 사용자 승인 (이 기획안의 문구·범위)
2. 작업 브랜치에서 위 변경안 적용 → PR → 검토 → 병합
3. 다음 신규 그림책 1권에 시범 적용하고, 콜라주 재발 여부와 재시도 횟수를 비공개 기록으로 확인
4. 효과가 없으면 문구를 늘리지 말고 원인 구분(§3-2 항목 10) 결과에 따라 조립 단계 개선 과제를 연다
