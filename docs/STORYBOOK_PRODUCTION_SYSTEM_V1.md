- 작성일: 2026-11-25
- 상태: 최종 기획안 (구현 전)
- 적용: 신규 생활·체험·과학동화, 개인 창작자 1인 + AI
- 기준: [제작 가이드 v3.1](STORYBOOK_GUIDELINES.md), [이미지 가이드 v2.3.1](ILLUSTRATION_STYLE_GUIDE_V2.3.md), [도서관 운영](BOOK_LIBRARY_OPERATIONS.md)

## 1. 추진 배경
원고, 스토리보드, 이미지 생성·검수, HTML 조립, 배포의 반복 결정을 표준화한다. 토스 디자인 시스템의 원리를 개인 제작에 적용하되 기업형 관리 체계는 도입하지 않는다.

## 2. 추진 목표
제작시간 단축, 캐릭터·그림체 일관성, 불필요한 재생성 최소화, 본문·삽화 일치, 부분 수정·복구 편의, 모바일 품질 표준화, 사용자 개입 최소화.

## 3. 핵심 설계 원칙
| 작품별 변수 | 공통화 |
|---|---|
| 실제 경험·사건·대화·감정 | HTML 레이아웃 |
| 장소·계절·날씨 | 글꼴·여백·색상 |
| 등장인물·의상 | 그림체 접두문·이미지 유형 |
| 학습 주제·사실·전개 | 압축·검수·배포 |

기존 가이드라인을 운영 원본으로 유지한다. SPS는 실행 구조이며 가이드를 대체하지 않는다. AI가 기록을 담당하고 사용자는 방향과 판단이 필요한 사항만 확인한다. 신규 작품 한 편부터 적용하며 기존 작품은 소급 변경하지 않는다.

## 4. 시스템 구성
| 계층 | 구성 | 역할 |
|---|---|---|
| L1 | 공통 자산 | 캐릭터·스타일·색상·글꼴 |
| L2 | 컴포넌트 | 표지·본문·삽화·발견 노트 |
| L3 | 제작 패턴 | 이야기 구조·이미지 구도 |
| L4 | 워크플로 | 신규·부분 수정·복구 |
| L5 | 품질 통제 | 검수·재시도·변경·배포 |

각 계층은 독립 변경 가능하도록 설계한다.

## 5. 공통 자산 라이브러리
캐릭터 시트, 얼굴·헤어·비율, 표정·자세, 반복 등장인물, 작품별 의상·액세서리를 분리한다. 공통 프롬프트, 골든 샘플 2~3장, 조명·색감·질감, A/B 공통 화풍, C 실사형 기준을 재사용한다. 골든 샘플 우선, 직전 그림은 보조 참조다. 실제 이름·사진·상세 캐릭터 자료·식별 생활정보는 비공개 작업 공간에만 보관한다. 공개 GitHub에는 일반화된 규칙과 공개 가능한 완성물만 둔다.

## 6. 스토리 패턴 라이브러리
| ID | 유형 | 흐름 |
|---|---|---|
| P01 | 여행·체험 | 출발→체험→발견→추억 |
| P02 | 일상 | 상황→작은 사건→행동→변화 |
| P03 | 감정·사회성 | 욕구→갈등→감정 이해→해결 |
| P04 | 탐구·발견 | 질문→관찰→비교→발견 |
| P05 | 성장·추억 | 도전→경험→성취→기억 |

AI가 제안하되 혼합·생략 가능. 실제 사건·대화를 왜곡하거나 교훈을 강제하지 않는다. 본문 공백 포함 1,500~2,500자, 권장 2,000~2,200자. 예외는 기존 가이드에 따르며 장면 수는 유연하게 정한다.

## 7. 이미지 구도 패턴
| 유형 | 목적·구도 | 텍스트 |
|---|---|---|
| A | 행동·감정 미디엄샷, 인물 25~40%, 클로즈업 40~60% 참고 | 이미지 내 금지 |
| B | 풍경 와이드샷, 인물 15~25% 또는 생략 | 이미지 내 금지 |
| C-1 | 사실적 단일 대상 근접 관찰 | 한국어 발견 노트 필수 |
| C-2 | 독립 대상 이미지 비교 | 한국어 비교 설명 필수 |

4:3 가로 기본, 점유율은 권장값. A/B 따뜻한 시네마틱 2D, C 사실적 관찰 표현. C형은 HTML/CSS 텍스트 합성 우선, 상세 필수 요소는 이미지 가이드 준수. 생성형 실사와 실제 촬영 증거 구분. 장면별 독립 생성, 이야기 콜라주 금지, C-2 복수 자산 허용. 대표 구도 카드는 시범 제작에서 확보한다.

## 8. 공통 HTML 템플릿
| ID | 컴포넌트 | 기능 |
|---|---|---|
| T01 | 표지 | 제목·대표 이미지·소개 |
| T02 | 일반 장면 | 삽화·본문 |
| T03 | 발견 노트 | C-1 관찰 이미지·설명 |
| T04 | 비교 카드 | C-2 비교 이미지·설명 |
| T05 | 마무리 | 이야기 종료·여운 |
| T06 | 독서 도구 | 글자 크기·인쇄·책장 이동 |

모바일 우선 세로 스크롤, 이미지 비율 유지, 한글 글꼴·줄간격, 발견 노트 디자인, 인쇄/PDF, alt·제목 구조·접근성을 공통화한다. 기본은 독립형 단일 HTML: 제작 시 템플릿과 데이터를 분리하고 출력 시 이미지·CSS·기능을 내장한다. 별도 이미지 웹 배포는 선택사항. 템플릿 변경은 기존 작품에 자동 반영하지 않고 별도 재빌드·검수한다.

## 9. 장면 데이터 및 빌드 구조
기존 image-manifest.json을 확장하고 별도 중복 대장은 만들지 않는다. 작품 정보: ID·제목·가이드 버전·패턴·예외. 장면: ID·순서·본문·유형·핵심 순간·구도·등장인물·필수 자산·학습 설명. 자산: ID·장면 연결·경로·상태·시도 횟수·본문/시각 명세/파일 해시·검수 결과. 필드명은 기존 구현과 대조 후 확정한다.

빌드 순서: 필수 자산 확인→승인 상태·변경 확인→디코딩·최적화→순서별 조립→Base64 내장→HTML 이스케이프·경로 제한→C형 텍스트·매핑 확인→독립 HTML 출력→품질 검사. 실패 시 기존 정상 결과물을 덮어쓰지 않는다.

## 10. 제작 워크플로
- A 신규: 소재→방향→원고→스토리보드→장면별 생성·검수→조립→최종 확인→게시.
- B 부분 수정: 대상 지정→영향 확인→재사용 판단→필요 장면만 수정→재검수→게시.
- C 기술 복구: 오류→정상 자산 확인→경로·압축·HTML 수정→기능 검증→공개 URL 확인. 정상 이미지를 재생성하지 않는다.

사용자 확인은 원고·방향과 최종 결과·게시 두 시점 중심. 중대한 사실 변경, 취향 판단, 예산 초과, 기존 가이드상 승인 필요 예외는 추가 확인. 예외 이유·범위는 manifest notes 한 줄로 기록하되 승인 요건은 유지한다.

## 11. 이미지 생산 및 품질 통제
| 내부 상태 | 사용자 표시 |
|---|---|
| pending | 대기 |
| generating | 진행 중 |
| review | 검수 중 |
| approved | 완료 |
| stale | 재확인 필요 |
| blocked | 확인 필요 |

기존 6개 상태와 해시 3종 유지. 승인 이미지 재생성 금지 원칙, 본문 변경 시 stale 검토, 단순 문구 수정은 재승인, 시각 불일치만 교체. 최초 1회+수정 2회, 3회 실패 시 중단·원인 분석·재개 승인. 기존 시도 이력과 중단 복구 규칙 준수. 자동화 미구현은 수동으로 표시한다.

| 오류 | 내용 | 처리 |
|---|---|---|
| E0 | 개인정보·잘못된 대상 | 필수 수정 |
| E1 | 핵심 불일치·누락·금지 콜라주 | 필수 수정 |
| E2 | 경미한 구도·색상 | 원칙 유지 |
| E3 | 취향 | 필요시 수정 |

## 12. 최종 품질 검수
자동 검증 대상: 본문 글자 수, 필수 자산, 디코딩·형식, 순서·매핑, 중복·해시, HTML·링크, C형 필수 텍스트, 개인정보 문자열, 390px 모바일 가로 스크롤.
AI 시각 검수: 본문·삽화 일치, 캐릭터, 얼굴·손·신체, 학습 사실성, 콜라주·문자, C형 한글 가독성, 전체 균형.
사용자: 콘택트 시트 또는 완성 HTML 중심으로 정서와 만족도 확인. 필수 오류는 평균 점수로 상쇄하지 않는다. 실제 미실행 검사는 완료 표시 금지.

## 13. 최소 성과 측정
| 지표 | 기준 |
|---|---|
| 전체 생성 시도/최종 승인 자산 | 잠정 1.3 이하 |
| 불필요 반복 생성 | 0건 |
| 작품당 총 제작시간 | 실측 |
| 필수 오류 | 게시 시 0건 |

실패·중단 시도 포함, 미완성 자산 별도 기록. 최초 통과율·사용자 개입은 자동 수집 가능할 때 보조 활용. 경과시간과 실제 작업시간 구분 및 대기시간 포함 여부 명시. 외부 기업 수치를 목표로 사용하지 않는다. 신작 1편 검증 후 3~5편 실측으로 조정한다.

## 14. 저장소 및 작업 공간 운영
GitHub 목표 구조: docs/ (가이드·SPS·운영), templates/storybook.html, scripts/build_storybook.py (통합 빌드·검증 진입점), books/ (완성 HTML), assets/ (공개 표지·공통 자산), index.html (책장). 기존 구조 확인 후 경로 확정.
비공개 ChatGPT 작업 공간: 소재·실제 경험, 원고·스토리보드, 캐릭터 참조, 작업 JSON·이미지·검수·진행 현황. Notion DB는 필요성 확인 전 보류.
운영 규칙 원본은 기존 가이드. 중복 제안 문서는 원문 대조 후 보관 처리. README의 v2.0 및 3권 표기는 확인했으나 전체 books/ 목록·대표 버전·중복 문서는 전수 검증 전이다.

## 15. 구현 계획
### Phase 1. 공통 제작 기반
기존 HTML 비교·공통 요소 추출, 템플릿, 매니페스트 확인, 통합 빌드·검증, 스토리 패턴 5종·구도 카드 4종. 완료: 장면 데이터와 자산으로 독립 HTML 생성.
### Phase 2. 신규 동화 시범
신작 1편 선정, 자산·패턴 적용, 독립 이미지 생성, 매니페스트 기록, 조립·검수·시간 측정. 완료: 기존 품질 기준 충족 동화 1편.
### Phase 3. 수정·복구 검증
본문 변경, 기존 이미지 재사용, 필요한 이미지 교체, 깨진 링크·이미지 복구, 중단 재개, 모바일·인쇄 시험. 완료: 전체 재제작 없는 부분 수정·복구.
### Phase 4. 운영 최적화
README와 실제 공개 목록 대조, 대표작·이전 버전 구분, 중복 문서 보관, 3~5편 실측, 불필요 관리 간소화. 별도 Studio·대시보드·고급 유사도 검사는 실제 필요 시 검토.

## 16. 제외 범위
기존 작품 일괄 재제작, 협업·기여자 관리, 다단계 승인, 성숙도 평가, 임의 가중 부채 지수, ROI/NPV/DID, 외부 생산성 수치, 별도 Notion DB·불필요 웹앱.

## 17. 최종 완료 기준
- 공통 템플릿 신규 제작, 승인 이미지 재사용, 변경 영향 확인, 장면 단위 수정 가능.
- 필수 오류 0건, 모바일·인쇄 정상, 개인정보 기준 충족.
- 사용자 게시 결정 후 실제 공개 URL 확인.
- 제작시간·이미지 생성 횟수 측정 가능.

## 18. 결론
창작 결과가 아니라 반복 판단과 작업을 표준화한다. 사용자는 경험·방향·최종 결과에 집중하고 AI는 원고 정리·생성·검수·조립·복구를 담당한다. 공통 템플릿 하나, 장면 데이터 하나, 빌드·검증 진입점 하나부터 시작한다. 작품이 쌓일수록 제작은 간편해지고 품질은 향상되는 환경을 목표로 한다.

현재 기획안만 확정한다. 템플릿·스크립트·자동화·시범 제작은 미구현이며 기존 작품과 가이드 변경은 범위 밖이다.
