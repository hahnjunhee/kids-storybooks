# Storybook Production System (SPS) v1.0 — 1인 생활동화 제작 통합 기획안

- 작성일: 2026-11-25
- 상태: 신규 작품 시범 적용 제안 (구현 완료 아님)
- 기준: [제작 가이드 v3.1](STORYBOOK_GUIDELINES.md), [이미지 공개 운영본 v2.3.1](ILLUSTRATION_STYLE_GUIDE_V2.3.md), [도서관 운영](BOOK_LIBRARY_OPERATIONS.md)
- 연구 배경: 토스 디자인 시스템 사례의 반복 의사결정 표준화. 기업의 성과 수치는 개인 이미지 제작에 전용하지 않는다.

## 1. 목표와 범위
한 사람이 실제 경험을 바탕으로 아이에게 읽어 줄 동화를 만든다. 사건, 감정, 대화, 장소, 학습 사실은 작품마다 달라야 한다. 레이아웃, 그림체 접두문, 압축 시작값, 글꼴, 검수와 출력 방식은 재사용한다. 기존 작품은 소급 변경하지 않는다. 협업, 위원회, ADR, 성숙도 평가, ROI/NPV, DID, 별도 대시보드 및 Notion DB는 범위 밖이다. 사용자 창작 방향과 최종 게시 결정은 유지한다.

## 2. 재사용 계층
- 기초: 공개 가능한 스타일 접두문, 색상·타이포그래피·여백, 압축 프로파일. 캐릭터 시트·골든 샘플·실사진·상세 설정은 비공개 작업 공간에만 둔다. 의상·계절·장소는 작품별 변수다.
- 컴포넌트: 표지, 일반 장면, C-1 발견 노트, C-2 비교 카드, 글자 크기 조절, 인쇄, 책장 링크.
- 패턴: 아래 이야기 흐름과 이미지 구도 카드를 독립적으로 선택한다.
- 작업: 신규 제작, 부분 수정, 기술 복구의 세 경로.
- 운영: 기존 가이드의 필수 품질 조건, 상태·재시도·변경 영향 관리만 사용한다. 새로운 승인 계층을 만들지 않는다.

## 3. 이야기 패턴 (선택 사항)
P01 여행·체험: 출발→체험→발견→추억.
P02 일상: 상황→작은 사건→행동→변화.
P03 감정·사회성: 욕구→갈등→감정 이해→해결.
P04 탐구·발견: 질문→관찰→비교→발견.
P05 성장·추억: 도전→경험→성취→기억.
혼합·생략 가능. 실제 사건과 대화를 패턴에 맞추어 왜곡하지 않는다. 학습 노트나 교훈을 억지로 넣지 않는다. 본문 1,500~2,500자 및 예외 승인 규칙은 기존 가이드에 따른다.

## 4. 구도 카드 (기존 이미지 규칙의 참조용 요약)
| 유형 | 기본 구도 | 텍스트 |
|---|---|---|
| A | 인물·행동 미디엄샷, 인물 25~40% 참고, 감정 클로즈업 40~60% | 이미지 내 금지 |
| B | 풍경 와이드샷, 인물 15~25% 또는 생략 | 이미지 내 금지 |
| C-1 | 사실적 대상 근접 관찰, 제목 배너와 발견 노트 | 최종 화면 한국어 제목·발견 노트 필수 |
| C-2 | 개별 대상 이미지와 비교 배치 | 최종 화면 한국어 비교 설명 필수 |

4:3 가로 기본, 점유율은 권장값이다. A/B는 동일한 따뜻한 시네마틱 2D, C는 실사형이며 생성 이미지임을 구분한다. C-1/C-2 상세 필수 요소는 이미지 가이드가 원본이다. C형 텍스트는 HTML/CSS 합성 우선. 장면별 독립 생성, 비교 카드 복수 자산 허용, 이야기 콜라주 금지. 구도 카드의 실제 시각 샘플은 시범 제작에서 확보한다.

## 5. 신작용 공통 HTML 빌드 설계
기존 단일 HTML 배포를 유지한다. 공개 가능한 공통 템플릿 하나와 빌드/검증 진입점 하나를 목표로 한다. 작업용 JSON과 이미지 원본은 비공개로 보관한다. 공개 저장소에는 일반화된 템플릿·코드·완성 HTML·공개 표지만 둔다. 별도 이미지 배포는 작품별 선택이다.

제안 경로: templates/storybook.html, scripts/build_storybook.py. 아직 생성하지 않는다. 기존 구현과 충돌 여부를 먼저 확인한다. 입력은 기존 image-manifest.json을 확장하여 book(title, slug, spec_version, notes), scenes(id, text, type, visual_spec, required_asset_ids, learning_card), assets(id, scene_id, path, status, attempts, text_hash, visual_spec_hash, sha256, checks)로 구성한다. 필드명은 구현 전 기존 스키마와 대조한다. 별도 중복 관리대장은 만들지 않는다. 빌드는 승인된 자산만 읽고 HTML 이스케이프, 경로 제한, 이미지 디코딩, Base64 내장, 순서·매핑·필수 텍스트 검증 후 출력한다. 실패하면 기존 완성 파일을 덮어쓰지 않는다. 모바일 390px, 글자 크기, 인쇄, 접근성, 공개 URL 검증은 실제 실행 여부를 구분한다.

## 6. 경량 작업 흐름
신규: 소재→원고·방향 확인→스토리보드→장면별 생성·검수→조립→최종 확인·게시.
부분 수정: 대상 장면 지정→본문/시각 명세 변경 영향 확인→기존 자산 재검수→필요한 것만 교체→전체 필수 검사→게시.
기술 복구: 정상 자산 확인→경로·압축·HTML 수정 우선→공개 URL 확인. 이미지 재생성은 최후 수단이다.

사용자 확인은 원고·방향과 최종 결과 중심으로 줄인다. 취향 또는 중대한 사실 변경, 재시도 예산 초과, 기존 가이드상 승인 필요 예외는 별도 확인한다. 예외 기록은 manifest notes에 이유와 범위 한 줄이면 충분하나 기존 승인 요건을 우회하지 않는다.

## 7. v3.1 통제의 경량화
클로드의 상태·시도 예산·승인 자산 보호 우선 적용 의견은 수용한다. 단, 기존 6개 상태(pending/generating/review/approved/stale/blocked), 본문·시각 명세·파일 해시, E0~E3 분류의 의미와 필수 검수는 삭제하지 않는다. 사용자 화면에는 대기/진행/완료/확인 필요 정도로 묶어 보여도 내부 상태는 보존한다. 본문 변경은 stale 재검토, 단순 문구 수정은 기존 이미지 재승인, 시각 불일치만 재생성한다. 최초 1회+수정 2회, 초과 시 blocked 및 재개 승인. 시도·해시·검수 기록은 가능한 범위에서 자동 수집하고 미구현은 수동으로 표시한다. 원자적 잠금이나 자동 실행을 구현 전 보장하지 않는다. 개인정보·필수 자산·본문 일치·C형 텍스트·콜라주·깨진 링크 등 필수 실패는 게시 차단이다.

## 8. 최소 측정
기존 핵심 KPI(전체 생성 시도/최종 승인 자산 수, 잠정 1.3 이하; 불필요 반복 0건)를 유지한다. 추가 핵심 지표는 작품당 총 소요시간 하나다. 시작~최종 검수의 경과시간과 실제 작업시간을 구분할 수 있으면 함께 기록하고 대기시간 포함 여부를 명시한다. 기존 최초 통과율 등 보조 지표는 자동 기록 가능할 때만 집계한다. 실패·중단 시도와 미완성 자산을 숨기지 않는다. 신작 1편으로 실행 가능성 확인 후 3~5편 실측으로 목표를 조정한다. 외부 연구 절감률을 목표로 사용하지 않는다.

## 9. 저장소 정리와 역할
GitHub는 공개 규칙·템플릿·코드·완성본 원본, 비공개 ChatGPT 작업 공간은 소재·캐릭터·작업 JSON·검수 중심이다. Notion은 당분간 불필요하다. 별도 Studio 웹앱은 실제 반복 불편이 확인될 때만 검토한다.
README가 가이드 v2.0과 3권만 표시하는 것은 확인했다. 다만 books/ 파일 수 및 버전별 공개 대표작 여부는 전수 확인하지 못했다. 공개 책장 index.html과 실제 파일을 대조한 뒤 대표작과 이전 버전을 구분해 목록을 정리한다. proposals의 중복 여부는 원문 대조 후 보관 처리하고 운영 규칙의 원본은 docs 가이드로 유지한다. 이 기획안은 가이드를 복제하거나 대체하지 않는다.

## 10. 시범 적용 완료 조건
1. 기존 코드·스키마 확인, 공통 템플릿 및 빌드/검증 진입점 구현.
2. 신작 1편의 비공개 JSON과 장면별 독립 이미지로 실제 조립.
3. 본문 변경 후 기존 자산 재사용 및 중단 복구 시험.
4. 필수 실패 0건, 모바일·인쇄·C형 텍스트·개인정보 확인.
5. 사용자 게시 결정 후 커밋 및 공개 URL 확인.
6. 생성 시도와 총 소요시간 기록, 불필요한 관리 항목만 간소화.

현재는 통합 기획안이며 템플릿·스크립트·자동화·신작 시범은 미구현이다. 기존 가이드와 작품은 변경하지 않는다.
