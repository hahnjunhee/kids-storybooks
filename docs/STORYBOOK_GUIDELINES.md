# 그림책 제작 가이드라인 v3.1.3

> 적용: 공개 그림책 저장소 · 2026-11-22 · 기존 작품의 창작적 내용은 보존하고 공개 식별정보만 최소 수정

## 1. 핵심 원칙과 우선순위

1. 사용자가 작품별로 확정한 조건
2. 사실관계·원작 핵심 사건·대화·정서 보존
3. 2022년생 여자아이 독자의 이해도, 읽기 경험, 접근성
4. 삽화의 일관성, 완성도와 기술적 안정성
5. 권장 글자 수·장면 수·용량 등 최적화 목표

**원칙과 목표값을 구분한다.** 신규 생활동화 본문은 공백 포함 1,500~2,500자를 준수한다. 원작 보존이 필요한 예외는 사용자 승인 후 적용한다. 장면 수는 작품 특성에 따라 유연하게 판단한다.

### 공개 이름·개인정보 정책

- 공개 저장소의 제목, 본문, 설명, 메타데이터, 파일명, 이미지 대체 텍스트에 **실제 아동 이름을 쓰지 않는다**.
- 주인공의 기본 별칭은 **루아**. 에피소드별 다른 별칭을 쓸 수 있으며, 이름이 불필요한 문장은 이름 없이 자연스럽게 쓴다. 제목에도 이름은 선택사항이다.
- 캐릭터 외형·그림체와 이름은 **서로 독립**적으로 관리한다. 공개 제작 문서는 기본 연령대와 일반적인 인물 묘사만 기록한다.
- 비공개 캐릭터 설정·기준 이미지·별칭 기록은 공개 저장소에 올리지 않는다. 실사진, 구체적인 생활 장소, 학교 등 식별정보도 공개하지 않는다.
- **현재 파일에서 이름을 지워도 Git 과거 커밋, 캐시, 외부 링크에는 흔적이 남을 수 있다.** 이력 재작성은 별도 영향 분석 후 진행한다.


> **이미지 유형별 상세 기준:** [그림책 이미지 제작 가이드라인 v2.4](ILLUSTRATION_STYLE_GUIDE_V2.3.md). A/B는 시네마틱 2D, C는 실사형 관찰 이미지이며 **C형 최종 화면에는 한국어 제목·발견 노트 또는 비교 설명 텍스트가 반드시 표시되어야 한다.**

## 2. 콘텐츠와 캐릭터 제작 표준

| 항목 | 권장 시작값 | 예외 및 판단 |
| --- | --- | --- |
| 본문 | 공백 포함 1,500~2,500자 (권장 2,000~2,200자) | 범위 내에서 내용에 따라 조정 |
| 장면 | 10~12장면 | 사건 단위로 구성 |
| 장면당 분량 | 2,100자/12장면 = 평균 175자 | 장면별 강제 제한 없음 |
| 예상 낭독 | 작품별 산정 | 글자 수/분당 낭독 글자 수 + 그림 관찰·대화 시간 |
| 흐름 | 상황 → 사건 → 발견 → 감정 → 마무리 | 자연스러운 구어체와 대화 |
| 발견 노트 | 필요한 경우 1~3개 | 억지로 추가하지 않음 |

### 본문 분량 산정

- 순수 동화 본문의 공백과 문장부호를 포함하여 실제 문자 수를 계수한다. 줄바꿈은 공백 하나로 정규화하고 연속 공백은 하나로 처리한다.
- 제목, 장면별 소제목, 삽화 설명, 발견 노트, 제작 메모는 제외한다.
- 최종 원고 확정 전에 1,500~2,500자 충족 여부와 실제 계수값을 확인한다. 불필요한 반복으로 분량을 채우지 않는다.

### 삽화·캐릭터 일관성

- 기본 그림체는 풍경과 조명이 풍부한 따뜻한 2D 애니메이션풍이다.
- 이름 대신 **the child protagonist**라는 역할 표현을 사용한다.
- 공개 공통 프롬프트 예시: `A Korean preschool-age girl born in 2022, natural child proportions, dark brown bob haircut with soft bangs, warm expressive eyes; detailed warm 2D storybook illustration, soft natural lighting, rich environmental backgrounds, consistent character appearance, no text, no speech bubbles, no collage.`
- 작품별 기준 이미지(골든 샘플) 2~3장과 캐릭터 시트, 동일한 스타일 접두문을 사용해 장면 간 일관성을 높인다. 상세 설정과 실제 이미지 참조는 비공개로 보관한다.
- **장면마다 독립 원본을 생성한다.** 스토리보드 확정 후 한 번의 이미지 생성 요청에는 하나의 이야기 장면만 포함한다. 서로 다른 장면을 한 프롬프트에 나열하거나 콜라주를 잘라 장면으로 사용하지 않는다. C-2 비교 카드의 개별 관찰 사진과 검수용 콘택트 시트는 이야기 장면 콜라주와 구분한다.
- 일반 삽화는 문구 없이, 학습 카드에는 짧은 제목·관찰 포인트를 넣을 수 있다. 학습 내용은 HTML 텍스트로도 제공한다.
- 인물이 풍경을 가리지 않도록 구도를 잡되, 화면 점유율 20~35%는 권장 참고값이지 합격 기준이 아니다.
- 과학·자연 사실은 검증한다. 실제 생물 묘사가 중요한 학습 카드는 사실적인 이미지로 구별한다.

### 스토리보드 확정 및 변경 관리

- 이미지 생성 전에 전체 원고를 정리하고 페이지별 스토리보드를 확정한다. 장면 ID, 해당 본문, A/B/C-1/C-2 유형, 한 장면의 핵심 순간, 구도·배경·등장인물, 필요한 이미지 자산과 C형 학습 텍스트를 기록한다.
- 스토리보드 확정 후 장면 구성은 잠근다. 수정이 필요한 경우 영향받는 장면과 자산만 다시 제작하며 이미 검증된 다른 장면은 재사용한다. 원작의 핵심 사건과 정서는 유지한다.
- 장면별 자산 개수는 반드시 1개일 필요가 없다. C-2 비교 사진, 표지, 추가 학습 카드 등은 스토리보드에 별도로 명시한다.

## 3. 기술 프로파일

### 배포 방식

- **기본: 독립형 단일 HTML.** 이미지 Base64 내장, 세로 스크롤, 모바일 우선, 오프라인 열람 가능.
- 신규 작품은 상단 고정 토글로 세로 스크롤(최초 기본)과 페이지 넘기기(선택)를 전환한다. 동일 장면 DOM·이미지를 공유하며 전환 시 읽던 장면 유지, 이전·다음 버튼·좌우 스와이프·페이지 표시를 제공한다. 긴 장면은 세로 이동 허용, 인쇄는 모든 장면 출력. 외부 라이브러리 없이 오프라인 동작. 500KB 목표 유지. [공통 열람 템플릿](../templates/storybook.html) 참고. 읽기 방식 UI는 공통 플레이어(`tools/narration/`)가 삽입한다(아래 '낭독(듣기)'). 기존 작품 소급 없음, 단 낭독 UI와 관련 메타데이터는 예외로 사용자 승인 후 한 권씩 적용한다.
- **선택: 웹 배포형 HTML.** 이미지를 별도 WebP 파일로 관리하여 캐시·지연 로딩 활용. 작품별 명시적 선택이 있을 때 적용한다.
- 단일 HTML과 별도 이미지 보관은 **동시에 강제하지 않는다**. 고해상도 원본은 공개 저장소 밖에 보관한다.
- 모바일에서 이미지 다음 본문을 읽고, 데스크톱에서는 균형 있게 배치한다. 이미지 비율 유지(`object-fit: contain` 우선), 글자 크기 조절, 인쇄·PDF, `lang="ko"`, 적절한 제목 구조·alt 텍스트를 제공한다.

### 낭독(듣기)

기준: [통합 기획안 v1.1](../proposals/2026-11-28-narration-feature-proposal.md). 도구와 절차: [tools/narration/README.md](../tools/narration/README.md).

- **적용과 작품 상태:** 신규 작품은 낭독을 포함해 출시하는 것을 기본으로 한다. 음성을 준비하기 어려우면 **사용자 승인하에** 읽기 전용으로 출시할 수 있고(`build.py --modes-only`), 낭독이 준비되면 그 작품만 업데이트한다. 작품은 세 상태로 구분한다: **읽기 전용**(열람 가능, 낭독 미제공, manifest `review_status=none`), **낭독 시범**(열람 가능, 낭독 검수 중, `pilot_unlistened`), **낭독 완료**(열람 가능, 낭독 승인 완료, `approved`). 기존 작품은 전기뱀장어 시범의 사용자 승인 후, 사용자가 승인한 책을 한 권씩 적용한다.
- **구조 규약(공통 열람 템플릿):** `main > section#scene0, scene1, …` 순번 id. 표지는 `h1`, 나머지는 `h2` + `.story p`. 낭독 범위는 제목·소제목·본문이다. 표지 소개 문단, 쪽 번호(`.eyebrow`), 제작 메모, 삽화 설명, 발견 노트·학습 카드(`section.activity`)는 낭독하지 않는다(선택 낭독은 후속). 규약을 따르면 `make_adapter.py`가 어댑터를 자동 생성하고, 따르지 않는 책은 어댑터를 손으로 작성한다. 규약 밖 `main` 직계 section(id 없음, scene 아닌 id, activity 아닌 class)과 장면처럼 보이는 non-section 요소는 조용히 건너뛰지 않고 오류로 멈춘다. 어댑터를 다시 만들 때는 `--update`를 쓰며 발음 치환·검수 기록은 보존되고, `--update` 없이는 기존 파일을 덮어쓰지 않는다.
- **음성 표준:** MeloTTS 한국어 KR 화자, A형 원본(무음·음량 후처리 없음). 장면별 MP3 `audio/<slug>/sNN.mp3`, mono 64kbps. 저장소에 직접 커밋하고 HTML에 Base64로 내장하지 않는다. 발음 치환은 낭독용 텍스트에만 적용하며 표시 본문은 바꾸지 않는다(숫자는 한글로 풀어 읽게 하는 등). 실명·실제 아동 목소리 복제 금지. 모든 음성에 "AI 음성"을 표시한다.
- **플레이어:** `tools/narration/`의 단일 소스를 `build.py`로 삽입한다(추가 전용: 기존 본문·삽화·스크립트 무변경, 삽입 블록을 지우면 원본과 바이트 동일). 사용자 탭으로만 시작하고 자동재생하지 않는다. 기본 재생 속도 1.15배, 선택지 0.9/1.0/1.15/1.25/1.35배. 읽기 방식(세로/페이지)과 낭독 UI는 플레이어가 제공하므로 책 HTML에 따로 만들지 않는다. 플레이어는 파일 하나이지만 **기본 열람 모듈**(세로/페이지 넘김·스와이프·방향키, 항상 동작)과 **낭독 모듈**(음성이 있을 때만)로 논리 분리한다. manifest 손상·버전 불일치·장면 연결 실패·MP3 누락·본문 불일치·낭독 코드 예외가 나도 낭독 UI만 끄고 기본 열람은 유지한다(브라우저 시험으로 검증). 오프라인에서도 글 읽기는 유지하고 음성은 보장하지 않는다(안내와 재시도).
- **무결성:** HTML 내 manifest의 `text_hash`(표시 본문), `synthesis_hash`(낭독 텍스트·발음·모델·설정), `audio_hash`(MP3)를 `verify.py`가 검사한다. 불일치하거나 검수되지 않은 음성은 배포하지 않는다. 본문을 고치면 해당 장면만 다시 합성한다. 본문에 숫자·영문이 있는 단위는 어댑터의 `pronunciation_review`에 `pending`으로 기록되고, 사람이 들어 확인한 뒤 `reviewed`로 바꾼다(`approved` 상태에서는 모두 `reviewed`여야 한다).
- **검수:** 사람이 전 장면을 듣고 `approved`로 올린 뒤 공개하는 것이 원칙이며 전 장면 청취 기록을 남긴다. 청취 전 시범은 사용자 승인 하에 `pilot_unlistened`로만 허용한다. 자동 검증과 브라우저 시험은 청취를 대체하지 않는다.
- **용량:** 신규 작품의 최종 HTML은 500KB(500,000바이트) 이하를 목표로 하며 **플레이어 삽입분(약 18KB)을 포함**한다. MP3는 HTML 밖에 두고 별도로 관리한다(전기뱀장어 2.5MB, 권당 2~3MB 추정). 삽화 품질 훼손이 예상되면 초과 사유를 어댑터 `size_exception`에 기록하고 사용자 승인을 받는다. `verify.py --max-html-bytes 500000`으로 점검한다. 기존 작품은 소급 판정하지 않는다(전기뱀장어 시범은 기존 작품으로 1.68MB).
- **라이선스:** 모델은 MIT로 확인했고, 학습 데이터·화자 출처가 공개되지 않은 위험은 사용자가 수용했다(기획안 §9). 출처가 공개되거나 확인되면 다시 검토한다.

### 이미지별 압축 시작값(품질 검증 후 조정)

| 유형 | WebP 시작값 | 우선 확인 |
| --- | --- | --- |
| 일반 장면 | 최대 800px, 품질 40 | 얼굴·손·풍경 |
| 사실적 자연 카드 | 약 1000px, 품질 60 | 생물 특징 |
| 글자 포함 학습 카드 | 약 1000~1200px, 품질 70 | 모바일 글자 선명도 |
| 표지 | 약 800px, 품질 50 | 목록 축소 화면 |

- 신규 단일 HTML은 **500,000 bytes 이하 기본 목표**로 제작한다. 과학 가독성 훼손 금지, 초과 사유 기록 및 사용자 승인 시 기존 1~2MB 권장 규격을 예외 적용한다. 기존 작품 소급 없음.
- Base64는 원본 바이너리 대비 대략 4/3 크기가 된다. 예: HTML·CSS·JS 25KB와 공통 플레이어 약 18KB를 포함한 총 목표 500KB, 이미지 13장일 때 압축 이미지 평균 예산 ≈ `(500-25-18)*3/4/13 = 26.4KB` (실제 복잡도에 따라 차등 배분).
- 글자가 포함된 카드에서 화질이 부족하면 압축 설정을 높이거나 **이미지 위에 HTML 텍스트를 분리**한다.
- 이미지의 생성 원본은 가로 1024px 이상 권장하되 배포 크기와 구별한다.

## 4. 품질 게이트와 측정

**자동 점검 후보**
- 본문 글자 수 실측(공백 포함 1,500~2,500자), 장면 수, **장면별 필수 자산의 충족·순서·매핑**, 이미지 누락·의도치 않은 중복 해시, 이미지 URL·Base64 형식. 이미지 수와 장면 수의 단순 일치는 합격 기준으로 사용하지 않는다.

## 5. 제작 승인과 GitHub 운영

1. **기획 확정:** 원고 방향·스타일·별칭을 정하고, 페이지별 본문·장면 ID·유형·핵심 순간·필수 자산·C형 텍스트를 포함한 스토리보드를 확정한다.
2. **제작·검증:** 비공개 캐릭터 기준 이미지와 스타일을 참조해 메인 대화에서 독립 프롬프트를 작성하고 **장면별 새 대화에서 하나씩 생성 → 즉시 검수·저장 → 통과 후 다음 장면**으로 진행한다. 실제 참조 첨부와 메인 대화 파일 접근을 확인한다. 실패한 장면만 복구하고, 이미지 최적화·C형 텍스트 합성·HTML 조립·낭독 합성과 삽입·자동 및 육안 검증을 거친다.
3. **최종 승인·게시:** 사용자가 게시를 요청하면 공개 저장소 반영, 책장 갱신, 공개 URL 확인(낭독 포함 작품은 전 장면 청취 승인 후)

- 공개 콘텐츠의 큰 변경과 개인정보 정리는 **작업 브랜치 → PR → 검토 → 병합**을 권장한다. 긴급 노출 정리는 승인 범위 내에서 직접 반영할 수 있다.
- 파일명은 이름 없는 영문 소문자·하이픈 slug를 사용한다. 예: `books/yeongheung-seaside.html`.
- 커밋 예: `book: add <slug>`, `book: fix <slug> scene 5`, `docs: update guidelines`.
- `books/`: 완성 HTML, `assets/`: 표지·선택형 웹 이미지, `audio/`: 낭독 MP3, `tools/narration/`: 낭독 도구, `docs/`: 제작·운영 기준, `index.html`: 공개 책장.
- **커밋 성공과 GitHub Pages 공개 성공은 별개**다. 실제 공개 URL 확인 여부를 보고한다.
- 기존 운영 기준은 [도서관 운영 문서](BOOK_LIBRARY_OPERATIONS.md)를 참고하되, 충돌 시 본 문서의 배포 프로파일 및 공개 이름 정책을 우선한다.

## 6. 이미지 생산 통제 — v3.1

신규 작품부터 시범 적용한다. 기존 작품은 소급 변경하지 않는다. 이미지 스타일 공개 운영본 v2.4, 본문 분량 및 기존 배포 프로파일은 유지하되 신규 단일 HTML 용량 목표는 §3을 따른다. 자동화 미구현 항목은 수동 운영 통제로 구분한다.

### 단계별 완료 조건
| 단계 | 완료 조건 |
|---|---|
| 기획 | 소재·독자·교육 목표 확정 |
| 본문 | 분량·사실·핵심 사건 검증 |
| 스토리보드 | 모든 필수 자산 ID·명세·본문 연결 확정 |
| 사전 검증 | 중복 구도 검토, 비공개 참조 및 실행 환경 확인 |
| 생성 | 모든 필수 자산 개별 검수 통과 |
| 조립 | 본문·자산 매핑 및 C형 텍스트 확인 |
| 품질 | 필수 오류 0건, 전체 콘택트 시트 및 모바일 검토 |
| 게시 | 사용자 게시 승인, 커밋 및 실제 공개 URL 확인 |

### 관리대장과 생성 전 차단
작품별 비공개 image-manifest.json 하나에 스토리보드와 자산 상태를 통합한다. 장면 ID와 자산 ID를 구분하여 C-2 복수 자산을 허용한다. 자산별 필수/금지 요소, 구도, 유형, 본문 연결, 명세 버전, text_hash, visual_spec_hash, 파일 경로·sha256, 시도 기록, 검수 근거를 관리한다. 공개 저장소에는 개인 식별정보나 비공개 참조를 넣지 않는다.

상태는 pending, generating, review, approved, stale, blocked 중 하나다. approved 자체가 잠금이며 별도 locked 값은 두지 않는다. 생성 직전 명세 확정, pending 상태, 기존 산출물 부재, 작업 중복 여부, 시도 예산, 직전 실패의 수정 조치를 확인한다. 요청 전에 generating 및 시도 ID를 저장하고 결과 파일을 저장한 뒤 review로 이동한다. 검수 통과 시 approved, 실패 시 원인 기록 후 pending 또는 blocked로 이동한다. 작업 중단 시 기존 파일·시도 기록부터 대조하고 생성 여부가 불명확하면 자동 재호출하지 않는다. 동시에 여러 작업을 실행하지 않는다. 원자적 잠금이나 도구 수준 차단이 구현되지 않으면 강제 통제라고 보고하지 않는다.

본문 해시 변경 시 관련 자산을 stale로 전환하여 의미와 시각 명세를 재검토한다. 단순 문구 수정이면 기존 파일을 재승인하고 해시를 갱신한다. 시각 명세 변경도 기존 이미지 적합성부터 검수하며 불일치할 때만 재생성한다. 승인 해시 변경은 사유 기록 및 재검수 없이는 허용하지 않는다.

### 재시도와 최소 수정
E0: 개인정보·잘못된 대상 등 치명 오류, E1: 핵심 본문 불일치·필수 자산 누락·금지 콜라주, E2: 경미한 구도·색상, E3: 취향. E0/E1은 반드시 해결하고 E2/E3은 원칙적으로 유지한다. 최초 1회+수정 2회가 기본 예산이다. 3회 실패 시 blocked, 원인 분석 및 명시적 재개 승인 후에만 추가 예산을 부여한다. 명세 버전별 및 전체 누적 시도를 보존하며 버전 변경으로 한도를 우회하지 않는다. 실패 원인·수정 조치·결과를 매회 기록한다. 경로·압축·텍스트 오류는 기존 파일 수정 우선, 핵심 사실을 훼손하지 않는 문구 수정 허용. SHA-256은 동일 파일 및 무단 교체 탐지용이며 반복 생성 차단은 ID와 상태가 담당한다. pHash는 향후 유사 후보 탐지용이다.

### 검수 및 개인정보
검수 항목별 result(pass/fail/pending), method(automatic/ai_visual/human), evidence, 검사 대상 해시를 기록한다. 실제 파일을 확인하지 않은 AI 판정이나 미실행 자동 검사를 통과로 표시하지 않는다. 자동 검사는 파일 디코딩·비율·경로·Base64·매핑·해시를, AI 시각 검수는 본문·구도·인물·콜라주·학습 사실을 담당한다. 사용자 확인은 전체 콘택트 시트와 최종 결과 중심으로 한 번 수행하며 미확인 상태를 숨기지 않는다. 프롬프트·참조 이미지·본문·매니페스트·파일명·메타데이터·커밋·이슈에서 실제 아동 이름과 식별정보를 원천 차단한다.

C형에는 아이 및 의인화 캐릭터를 등장시키지 않는다. C형은 그림과 한국어 텍스트를 분리 제작하여 최종 카드에 합성하는 것을 우선한다. 기존 v2.4의 HTML/CSS 최종 화면 합성 허용을 유지하며, 독립 이미지 납품이 필요한 경우 텍스트 포함 완성본을 별도로 내보낸다. A/B는 텍스트 금지 유지. 골든 샘플·캐릭터 시트를 우선 참조하고 직전 그림은 보조로만 사용한다.

### 시범 적용과 측정
Phase 1: 신규 동화 1편, 통합 JSON 하나와 기본 검증 스크립트 하나를 목표로 한다. 실제 파일 저장·재조회·중단 복구·참조 전달·부분 편집·한글 합성·해시 검사·배포 확인 가능성을 먼저 시험한다. 불가능한 기능은 수동 대안 또는 blocked로 기록한다.
Phase 2: 본문 변경 감지 자동화, C형 합성 개선, KPI 측정. Phase 3: 필요할 때 pHash, CI, 대시보드, 자동 재개.
핵심 KPI는 전체 생성 시도 수/최종 승인 자산 수(잠정 1.3 이하), 불필요한 반복 생성 0건이다. 보조 KPI는 최초 시도 통과 자산/최초 시도한 자산(80% 이상), 한도 도달 건수다. 실패·중단·재개 시도를 포함하고 미완성 자산 수를 별도 보고한다. 필수 오류 0건은 배포 조건이다. 과거 미검증 활용률은 기준선으로 사용하지 않는다. 신규 3~5편 실측 후 조정한다.
