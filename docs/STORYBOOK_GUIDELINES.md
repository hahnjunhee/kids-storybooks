# 지아 생활동화 제작 가이드라인

> 버전: v1.0 · 확정일: 2026-11-22  
> 적용 대상: 지아의 반짝반짝 책장에 추가하는 생활동화·과학 그림책  
> 기준 사례: 《지아의 반짝반짝 영흥도 여행》

이 문서는 원고 작성부터 삽화 생성, 학습 카드, HTML 제작, 압축, 검증, GitHub 게시까지의 **기본 제작 표준**이다. 기존 작품을 일괄 변경하라는 뜻은 아니다. 사용자가 개별 작품에서 명시적으로 지정한 조건은 이 가이드보다 우선한다.

## 1. 스토리 작성 기준

| 항목 | 기본 기준 |
| --- | --- |
| 독자 | 2022년생 지아, 만 4세 전후 발달 수준 |
| 분량 | 본문 약 3,000자(권장 2,800~3,200자) |
| 낭독 시간 | 약 12~15분을 목표로 하되 실제 낭독 속도에 따라 달라짐 |
| 장면 | 약 10~12장면 |
| 문체 | 따뜻하고 자연스러운 구어체, 소리 내어 읽기 좋은 문장 |
| 이야기 흐름 | 상황 → 사건 → 발견 → 감정 → 마무리 |
| 대화 | 지아와 가족 등 등장인물의 자연스러운 대화 |
| 교육 | 설명을 나열하지 않고 사건과 호기심 속에 자연스럽게 연결 |

- 실화·블로그 원작을 바탕으로 할 때 **원작의 핵심 사건, 장소, 대화, 정서적 흐름과 분량**을 가능한 한 보존한다.
- 과도한 축약, 원작에 없는 사실의 단정, 장면 간 갑작스러운 전환을 피한다.
- 숫자·자연·생활습관 등 배움은 이야기 흐름을 방해하지 않는 범위에서 포함한다.
- 분량·장면 수는 기본값이며 작품 특성에 따라 사용자의 승인을 받아 조정한다.

## 2. 생활동화 삽화 스타일

- 기본 그림체는 **따뜻하고 섬세한 2D 애니메이션풍**이다. 풍부한 배경, 부드러운 빛, 자연스러운 파스텔 색감과 장면의 분위기를 강조한다.
- 지아의 기본 외형은 **짙은 갈색 단발머리와 앞머리, 자연스러운 동아시아 유아의 비율**로 일관되게 유지한다. 장면별 의상·표정은 사건에 맞게 달라질 수 있다.
- 인물은 대체로 화면의 **20~35% 정도**로 표현하여 풍경·장소·행동 맥락이 충분히 보이도록 한다. 구도에 따라 예외는 가능하다.
- 일반 이야기 삽화에는 **문자, 말풍선, 설명 문구를 넣지 않는다**. 텍스트는 HTML 본문에서 제공한다.
- **장면별 독립된 고해상도 원본**을 생성한다. 여러 장면을 하나의 콜라주로 만든 후 잘라 쓰는 방식은 사용하지 않는다. 이는 해상도 저하와 피사체 잘림을 방지하기 위한 필수 규칙이다.
- 생성 원본은 가로 1024px 이상을 권장한다. **원본 생성 해상도와 배포용 압축 해상도는 별개**다.
- 사용자가 승인한 참고 이미지와 스타일을 우선하며, 승인 없이 다른 그림체로 전환하지 않는다.

## 3. 지식 탐구 페이지: 🔎 지아의 발견 노트

이야기 속 호기심을 과학·자연·사회·생활 지식과 연결하는 선택적 학습 콘텐츠다.

- 작품 내용에 맞춰 **1~3개 정도**의 학습 카드를 권장한다. 억지로 추가하지 않는다.
- 생물·갯벌·자연현상 등 실제 모습이 중요한 대상은 **실사에 가까운 사실적 이미지**를 우선한다. 일반 스토리 삽화의 애니메이션풍과 구별한다.
- 학습 카드 이미지에는 **귀여운 제목, 관찰 포인트, 짧은 한글 설명**을 넣을 수 있다. 이 규칙은 일반 이야기 삽화의 무문자 원칙에 대한 예외다.
- 핵심 설명은 유아가 이해할 수 있게 짧게 쓰되 과학적 정확성을 유지한다. 확인되지 않은 사실은 단정하지 않는다.
- 이미지 속 글자가 압축 후에도 읽히는지 반드시 확인한다.
- 이미지에 설명을 넣더라도 **HTML 본문에 같은 핵심 정보를 텍스트로 제공**하여 접근성·검색성·복사 가능성을 확보한다.
- 예시: 짱뚱어는 갯벌에서 움직이며 먹이를 찾고 피부·아가미 주변을 촉촉하게 유지해야 한다. 게는 다리가 열 개 있는 갑각류이며, 갯벌 생물은 원래 서식지에서 조심스럽게 관찰한다.

## 4. HTML 디자인과 기능

| 항목 | 구현 기준 |
| --- | --- |
| 기본 형식 | 이미지가 포함된 **단일 HTML 파일** |
| 읽기 방식 | 세로 스크롤 |
| 모바일 | 이미지가 먼저, 해당 장면의 본문이 이어지는 흐름 |
| 데스크톱 | 이미지·본문을 균형 있게 배치하는 반응형 구성 |
| 이미지 표시 | 원본 비율 유지, `object-fit: contain` 우선 |
| 금지 | 임의 크롭, 인물·배경 잘림, 과도한 빈 공간 |
| 가독성 | 충분한 글자 크기, 행간, 여백, 대비 |
| 기능 | 글자 크기 조절, 브라우저 인쇄 및 PDF 저장 |
| 접근성 | `lang="ko"`, 의미 있는 제목 구조, 이미지 대체 텍스트, 학습 내용의 텍스트 제공 |

- 외부 서버나 별도 이미지 폴더가 없어도 HTML 하나로 읽을 수 있도록 **이미지 Base64 내장**을 기본값으로 한다.
- 반응형 레이아웃은 실제 모바일 너비에서 본문과 삽화가 잘리지 않도록 확인한다.
- 표지·학습 카드·장면 삽화는 각각 용도에 맞는 표시 비율을 사용한다.
- 배포 페이지의 공통 디자인과 독서 편의 기능은 작품 간 가능한 한 일관되게 유지한다.

## 5. 이미지 최적화 및 파일 크기

### 기본 배포 프리셋: 최소 용량

| 항목 | 기본값 |
| --- | --- |
| 형식 | WebP |
| 최대 가로 해상도 | **800px** (원본 비율 유지) |
| WebP 품질 | **40** |
| HTML 포함 방식 | Base64 데이터 URI |
| 파일 크기 목표 | 가능하면 **약 1~2MB** |

- 영흥도 그림책 사례: 약 **5.91MB → 1.11MB**, 약 **81.3% 감소**. 이는 특정 작품의 결과이며 모든 작품에서 동일한 비율을 보장하지 않는다.
- **최소 용량은 목표이지 절대적인 상한이 아니다.** 작은 글씨가 있는 학습 카드나 정교한 생물 사진은 선명도를 위해 해당 이미지에 한해 해상도·품질을 높인다.
- 원본 고해상도 이미지는 재편집할 수 있도록 별도로 보관하는 것을 권장하되, 공개 배포 HTML에는 최적화 이미지를 넣는다.
- 압축 후에는 얼굴·손·동물의 주요 특징, 풍경, 한글 설명의 가독성을 확인한다.
- 향후 이미지 분리·캐시 전략은 필요할 때 별도로 검토하되, 단일 HTML이라는 현재 기본 정책을 임의로 바꾸지 않는다.

## 6. 품질 검증 체크리스트

게시 전에 아래 항목을 점검한다.

- [ ] 본문 분량이 약 3,000자인지 확인한다.
- [ ] 원작의 핵심 사건·대화·흐름이 유지되는지 확인한다.
- [ ] 장면별로 **독립된 서로 다른 삽화**를 사용하는지 확인한다.
- [ ] 지아의 외형과 인물 크기, 배경 표현이 일관적인지 확인한다.
- [ ] 모바일·PC에서 이미지와 본문이 잘리지 않는지 확인한다.
- [ ] 학습 카드의 한글 설명이 압축 후에도 읽히는지 확인한다.
- [ ] 계획한 장면·학습 카드의 이미지가 모두 HTML에 포함되는지 확인한다.
- [ ] 글자 크기 조절, 인쇄, PDF 저장 및 링크가 정상 작동하는지 확인한다.
- [ ] 최종 파일 크기와 압축 후 화질을 확인한다.
- [ ] GitHub에 올린 뒤 **공개 GitHub Pages URL에서 실제 열람이 되는지** 확인한다. 커밋 성공만으로 배포 성공이라고 단정하지 않는다.

검증하지 못한 항목은 완료라고 표시하지 않고, 남은 확인 사항을 사용자에게 명확히 알린다.

## 7. 제작·승인·배포 절차

1. **원고 확정** — 원작 반영 범위, 사건·대화·장면 수, 발견 노트 구성 확인
2. **삽화 스타일 확정** — 참고 이미지, 지아 외형, 배경 비중 및 그림체 승인
3. **이미지 제작** — 장면별 고해상도 독립 삽화 및 별도 학습 카드 생성
4. **HTML 통합** — 원고·이미지 결합, 반응형 배치, 독서 기능 적용
5. **압축 및 검증** — 최소 용량 프리셋 적용, 글자·화질·기능·용량 점검
6. **GitHub 배포** — 승인된 최종본 업로드, 책장 목록·표지·링크 갱신, 공개 URL 검증

### 변경 관리 원칙

- **사용자가 확정한 버전을 기준으로 개선한다.** 승인 없이 본문·그림체·핵심 장면을 변경하지 않는다.
- 사용자가 **게시를 명시적으로 요청한 경우에만** 공개 저장소에 반영한다.
- 기존 작품을 일괄 수정하지 않는다. 새 가이드라인은 이후 제작의 기본값이며, 기존 작품 수정은 별도 승인 사항이다.
- 배포 시 실제 변경 파일과 검증 결과를 간결하게 보고한다.
- 가이드라인을 수정할 때는 변경 이유와 버전을 함께 기록한다.

## 8. 저장소 내 역할

- `index.html`: 공개 책장과 작품 목록
- `books/`: 완성된 그림책 HTML
- `assets/`: 표지 등 공통 정적 자산
- `docs/STORYBOOK_GUIDELINES.md`: 이 문서 — **콘텐츠 제작 및 품질 표준**
- `docs/BOOK_LIBRARY_OPERATIONS.md`: 기존 **도서관 운영·등록 절차** (세부 운영 내용은 해당 문서 우선)
- `README.md`: 저장소 소개와 문서 진입점
