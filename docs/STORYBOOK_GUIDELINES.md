# 그림책 제작 가이드라인 v2.0

> 적용: 공개 그림책 저장소 · 2026-11-22 · 기존 작품의 창작적 내용은 보존하고 공개 식별정보만 최소 수정

## 1. 핵심 원칙과 우선순위

1. 사용자가 작품별로 확정한 조건
2. 사실관계·원작 핵심 사건·대화·정서 보존
3. 2022년생 여자아이 독자의 이해도, 읽기 경험, 접근성
4. 삽화의 일관성, 완성도와 기술적 안정성
5. 권장 글자 수·장면 수·용량 등 최적화 목표

**원칙과 목표값을 구분한다.** 원작이 길면 3,000자에 맞추기 위해 핵심 내용을 삭제하지 않는다. 장면 수와 분량 변경은 작품 특성에 따라 유연하게 판단한다.

### 공개 이름·개인정보 정책

- 공개 저장소의 제목, 본문, 설명, 메타데이터, 파일명, 이미지 대체 텍스트에 **실제 아동 이름을 쓰지 않는다**.
- 주인공의 기본 별칭은 **루아**. 에피소드별 다른 별칭을 쓸 수 있으며, 이름이 불필요한 문장은 이름 없이 자연스럽게 쓴다. 제목에도 이름은 선택사항이다.
- 캐릭터 외형·그림체와 이름은 **서로 독립**적으로 관리한다. 공개 제작 문서는 기본 연령대와 일반적인 인물 묘사만 기록한다.
- 비공개 캐릭터 설정·기준 이미지·별칭 기록은 공개 저장소에 올리지 않는다. 실사진, 구체적인 생활 장소, 학교 등 식별정보도 공개하지 않는다.
- **현재 파일에서 이름을 지워도 Git 과거 커밋, 캐시, 외부 링크에는 흔적이 남을 수 있다.** 이력 재작성은 별도 영향 분석 후 진행한다.


> **이미지 유형별 상세 기준:** [그림책 이미지 제작 가이드라인 v2.3](ILLUSTRATION_STYLE_GUIDE_V2.3.md). A/B는 시네마틱 2D, C는 실사형 관찰 이미지이며 **C형 최종 화면에는 한국어 제목·발견 노트 또는 비교 설명 텍스트가 반드시 표시되어야 한다.**

## 2. 콘텐츠와 캐릭터 제작 표준

| 항목 | 권장 시작값 | 예외 및 판단 |
| --- | --- | --- |
| 본문 | 약 3,000자(2,800~3,200자) | 원작 보존이 우선 |
| 장면 | 10~12장면 | 사건 단위로 구성 |
| 장면당 분량 | 3,000자/12장면 = 평균 250자 | 장면별 강제 제한 없음 |
| 예상 낭독 | 약 12~15분 | 글자 수/분당 낭독 글자 수 + 그림 관찰·대화 시간 |
| 흐름 | 상황 → 사건 → 발견 → 감정 → 마무리 | 자연스러운 구어체와 대화 |
| 발견 노트 | 필요한 경우 1~3개 | 억지로 추가하지 않음 |

### 삽화·캐릭터 일관성

- 기본 그림체는 풍경과 조명이 풍부한 따뜻한 2D 애니메이션풍이다.
- 이름 대신 **the child protagonist**라는 역할 표현을 사용한다.
- 공개 공통 프롬프트 예시: `A Korean preschool-age girl born in 2022, natural child proportions, dark brown bob haircut with soft bangs, warm expressive eyes; detailed warm 2D storybook illustration, soft natural lighting, rich environmental backgrounds, consistent character appearance, no text, no speech bubbles, no collage.`
- 작품별 기준 이미지(골든 샘플) 2~3장과 캐릭터 시트, 동일한 스타일 접두문을 사용해 장면 간 일관성을 높인다. 상세 설정과 실제 이미지 참조는 비공개로 보관한다.
- **장면마다 독립 원본을 생성한다.** 여러 장면을 한 장으로 생성하고 잘라 사용하는 방식은 금지한다.
- 일반 삽화는 문구 없이, 학습 카드에는 짧은 제목·관찰 포인트를 넣을 수 있다. 학습 내용은 HTML 텍스트로도 제공한다.
- 인물이 풍경을 가리지 않도록 구도를 잡되, 화면 점유율 20~35%는 권장 참고값이지 합격 기준이 아니다.
- 과학·자연 사실은 검증한다. 실제 생물 묘사가 중요한 학습 카드는 사실적인 이미지로 구별한다.

## 3. 기술 프로파일

### 배포 방식

- **기본: 독립형 단일 HTML.** 이미지 Base64 내장, 세로 스크롤, 모바일 우선, 오프라인 열람 가능.
- **선택: 웹 배포형 HTML.** 이미지를 별도 WebP 파일로 관리하여 캐시·지연 로딩 활용. 작품별 명시적 선택이 있을 때 적용한다.
- 단일 HTML과 별도 이미지 보관은 **동시에 강제하지 않는다**. 고해상도 원본은 공개 저장소 밖에 보관한다.
- 모바일에서 이미지 다음 본문을 읽고, 데스크톱에서는 균형 있게 배치한다. 이미지 비율 유지(`object-fit: contain` 우선), 글자 크기 조절, 인쇄·PDF, `lang="ko"`, 적절한 제목 구조·alt 텍스트를 제공한다.

### 이미지별 압축 시작값(품질 검증 후 조정)

| 유형 | WebP 시작값 | 우선 확인 |
| --- | --- | --- |
| 일반 장면 | 최대 800px, 품질 40 | 얼굴·손·풍경 |
| 사실적 자연 카드 | 약 1000px, 품질 60 | 생물 특징 |
| 글자 포함 학습 카드 | 약 1000~1200px, 품질 70 | 모바일 글자 선명도 |
| 표지 | 약 800px, 품질 50 | 목록 축소 화면 |

- 1~2MB는 **단일 HTML의 목표 용량**이지 배포를 막는 절대 제한이 아니다.
- Base64는 원본 바이너리 대비 대략 4/3 크기가 된다. 예: HTML·CSS·JS 100KB, 총 목표 1.5MB, 이미지 14장일 때 압축 이미지 평균 예산 ≈ `(1500-100)*3/4/14 = 75KB`.
- 글자가 포함된 카드에서 화질이 부족하면 압축 설정을 높이거나 **이미지 위에 HTML 텍스트를 분리**한다.
- 이미지의 생성 원본은 가로 1024px 이상 권장하되 배포 크기와 구별한다.

## 4. 품질 게이트와 측정

**자동 점검 후보**
- 본문 글자 수, 장면 수, 이미지 수·누락·중복 해시, 이미지 URL·Base64 형식
- 파일 바이트 크기, `lang="ko"`, alt, 내부 링크, 이름·기존 식별 접두어 노출 검사
- 390px 모바일 화면 가로 스크롤, 글자 크기 조절·인쇄 기능 브라우저 테스트

**사람이 확인할 항목**
- 원작 사건·감정 보존, 인물 일관성, 얼굴·손·배경, 학습 사실과 이미지 속 한글의 가독성
- 이름 치환 후 조사·대사·호칭의 자연스러움

품질 점수는 보조 평가(스토리 25, 삽화 25, 독서·학습 20, 기능·접근성 15, 배포 안정성 15)로만 활용한다. **이미지 누락·식별정보 노출·깨진 공개 링크 등 필수 실패는 평균 점수로 상쇄하지 않는다.** 자동화되지 않은 검사는 완료했다고 표시하지 않는다.

## 5. 제작 승인과 GitHub 운영

1. **기획 확정:** 원고 방향·장면·스타일·별칭 결정
2. **제작·검증:** 독립 삽화, HTML, 이미지별 최적화, 자동 및 육안 점검
3. **최종 승인·게시:** 사용자가 게시를 요청하면 공개 저장소 반영, 책장 갱신, 공개 URL 확인

- 공개 콘텐츠의 큰 변경과 개인정보 정리는 **작업 브랜치 → PR → 검토 → 병합**을 권장한다. 긴급 노출 정리는 승인 범위 내에서 직접 반영할 수 있다.
- 파일명은 이름 없는 영문 소문자·하이픈 slug를 사용한다. 예: `books/yeongheung-seaside.html`.
- 커밋 예: `book: add <slug>`, `book: fix <slug> scene 5`, `docs: update guidelines`.
- `books/`: 완성 HTML, `assets/`: 표지·선택형 웹 이미지, `docs/`: 제작·운영 기준, `index.html`: 공개 책장.
- **커밋 성공과 GitHub Pages 공개 성공은 별개**다. 실제 공개 URL 확인 여부를 보고한다.
- 기존 운영 기준은 [도서관 운영 문서](BOOK_LIBRARY_OPERATIONS.md)를 참고하되, 충돌 시 본 문서의 배포 프로파일 및 공개 이름 정책을 우선한다.
